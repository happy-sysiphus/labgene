# LabGene 상담 RAG 평가 스펙 v0.1 — 본실험 v3 사후 평가

작성일: 2026-09-29

상태: 본실험 v3(`artifacts/main-v3`, frozen `configs/frozen/main-v3.json`, 분석 계획
`docs/implementation/analysis-plan-v3.md`)에서 두 상담이 실제로 낸 답을 RAG 지표와 시뮬레이터 정답성으로 사후
채점하는 설계다. 본실험의 과제·예산·성공 기준·주지표(U27)·분석 계획은 바꾸지 않는다. v3 산출물은 읽기만 하고,
이 평가의 결과는 실험의 어떤 상태에도 되돌리지 않는다(하네스 스펙 §13.6).

## 1. 목적과 범위

**v3에서 일반 LLM 상담과 LabGene 상담이 내놓은 답이 받은 근거에 얼마나 충실한지, 그리고 추천이 실제로 맞았는지를
같은 잣대로 비교한다.** 본실험 주지표가 과제 해결까지의 행동 수를 본다면, 이 평가는 그 사이에 오간 상담 답의 품질을
본다.

범위 안:

- v3 실제 상담 전부에 대한 코드 지표(기계 검사, 추천 정답성)
- 조건당 최대 40건 표본에 대한 LLM 판정 지표(충실도, 모순률, 문맥 정밀도, 답변 관련성, 인용)
- 공개 보고서와 비공개 원자료

범위 밖: 스냅숏 재생과 템플릿 질문, 모범 답안이 있는 지식 질문셋, RAGAS 라이브러리, 구성요소 절제 실험, v1·v2 상담,
상담 모델 재호출.

## 3. 표본

### 3.1 모집단

main-v3 ledger의 `consult_exchanges` 전부. 답의 `status`가 `ok`가 아닌 상담(부분 답)은 부분 답 비율로만 보고하고
지표 계산에서 뺀다.

### 3.2 LLM 판정 표본

조건·과제마다 그 과제의 모든 시도에서 나온 `ok` 상담을 시간 순(에피소드 순서, 그 안의 행동 순서)으로 이어 붙이고,
n건 중 m = min(10, n)건을 위치 round(i·(n−1)/(m−1)), i = 0…m−1에서 고른다(m = 1이면 첫 건). 조건당 최대 40건이다.
선택 결과와 해시(`sample.json`)는 판정 모델을 처음 부르기 전에 기록하고, 이후 바꾸지 않는다.

### 3.3 문맥 복원

- 표본 상담마다 상담 모델이 받은 입력을 실험과 같은 코드 경로로 다시 만든다. ledger에서 질문, 그 에피소드의 앞선
  관측·무효 요청·상담, 남은 행동을 읽어 `ConsultRequest`를 만들고, 그 조건 상담기(`ProductAdvisor`,
  `BaselineAdvisor`)의 `knowledge()`와 `base_payload()`만 호출한다. 생성 호출은 하지 않는다.
- 상태는 main-v3 세트 상태(`state/<condition>/main_v2/rep1/`)의 사본을 쓴다. 기억은 그 상담이 속한 에피소드보다 앞선
  에피소드의 기록만 남긴다. 일반 조건 기억 요약은 실험 때의 캐시를 쓰고, 캐시가 없을 때만 요약 역할을 부른다.
- 상담 중 도구(search/open)로 연 자료는 기록에 남지 않아 복원하지 않는다.
- 복원 일치: 실제 답의 인용 id가 모두 복원한 전달 목록 안에 있으면 일치다. 아니면 불일치로 표시하고 채점은 그대로
  하며, 보고서에 불일치 건수를 적는다.

## 4. 지표

| 지표 | 정의 | 대상 | 계산 |
|---|---|---|---|
| 충실도 (주지표) | 사실 주장 중 문맥으로 뒷받침되는 비율 | 두 조건, 표본 | 판정 |
| 모순률 | 사실 주장 중 문맥과 모순되는 비율 | 두 조건, 표본 | 판정 |
| 사실 주장 비율 | 전체 주장 중 사실 주장의 비율 | 두 조건, 표본 | 판정 |
| 문맥 정밀도 | 문헌·KG 카드 중 쓸모 있는 카드의 순위 가중 정밀도 | 제품, 표본 | 판정 |
| 답변 관련성 | 답에서 역생성한 질문과 원 질문의 코사인 평균 | 두 조건, 표본 | 판정 + 임베딩 |
| 인용 재현율 | 사실 주장 중 뒷받침 문단을 답이 인용한 비율 | 두 조건, 표본 | 판정 결과를 코드로 대조 |
| 인용 정밀도 | 인용한 id 중 주장을 하나 이상 뒷받침하는 비율 | 두 조건, 표본 | 판정 결과를 코드로 대조 |
| 기계 검사 | `validation_issues` 종류별 건수(관측 수치 불일치, 범위 밖 후보, 받지 않은 자료 인용, 빈 필드) | 두 조건, 전부 | 코드(실험 기록) |
| 추천 성공률 | 1순위 후보가 성공 기준(숨은 TON 문턱 포함)을 채운 비율 | 두 조건, 전부 | 시뮬레이터 |
| 추천 정규화 점수 | 수율 조건을 채우면 TON ÷ 숨은 TON 문턱(성공에 필요한 최소 TON), 아니면 0 | 두 조건, 전부 | 시뮬레이터 |
| 추천 개선률 | 1순위 점수가 그 에피소드에서 상담 전까지 관측된 최고 점수보다 높은 비율 | 두 조건, 전부 | 시뮬레이터 |

정의 세부:

- **주장.** answer, reasoning, 각 후보의 rationale을 원자 주장으로 나눈다(limitations 제외). 각 주장을 사실(문헌·화학·
  관측에 대해 확인할 수 있는 진술)과 추론(예측·추천·판단)으로 나눈다. RAGAS 충실도는 모든 진술을 채점하지만, 상담
  프롬프트가 추론과 예측을 요구하므로 사실 주장만 채점하고 사실 주장 비율을 함께 보고한다. 사실 주장이 없는 답은 충실도
  평균에서 빼고 그 수를 적는다.
- **충실도 판정.** 문맥은 3.3에서 복원한 입력 전체다. 사실 주장마다 지지·모순·없음과, 뒷받침하는 문단 id 전부를 받는다.
  충실도 = 지지 수 ÷ 사실 주장 수, 모순률 = 모순 수 ÷ 사실 주장 수. "없음"에는 일반 지식으로는 맞는 진술도 들어간다.
  이 지표는 근거 충실도이지 참·거짓 판정이 아니다.
- **문맥 정밀도.** 제품이 전달한 문헌 카드와 KG 경로 카드를 전달 순서대로(문헌은 검색 순위, 그다음 KG 경로) 두고,
  카드마다 이 질문에 답하는 데 쓸모 있는지 판정한다(v_k ∈ {0, 1}). 값 = Σ_k(precision@k · v_k) ÷ Σ_k v_k이고, 쓸모 있는 카드가 없으면 0이다. 단순
  정밀도(Σ v_k ÷ K)도 함께 적는다. 일반 조건은 검색이 없어 해당 없음이다.
- **답변 관련성.** 답에서 그 답이 대답하는 질문 3개와 얼버무림 여부를 생성하고, gemini-embedding-2로 원 질문과의
  코사인 평균을 낸다. 얼버무린 답은 0이다.
- **인용 지표(ALCE 변형).** 상담 답은 문장별이 아니라 답 전체에 인용을 붙인다. 그래서 충실도 판정의 뒷받침 문단 id를
  원래 id로 되돌려 답의 `cited_source_ids`·`cited_observation_ids`와 대조한다. 인용 재현율 = 뒷받침 문단 중 하나라도
  인용된 사실 주장 수 ÷ 사실 주장 수. 인용 정밀도 = 뒷받침한 주장이 하나 이상인 인용 id 수 ÷ 인용 id 수.
- **추천 정답성.** 1순위는 `candidates[0]`이다. 후보가 없거나 공개 범위·제약을 벗어나면 점수 0, 성공 아님으로 두고
  "추천 없음/무효"로 따로 센다. v3와 같은 simulator id·version의 평가자 전용 시뮬레이터 워커로 돌리고,
  `PublicTask.is_success`로 성공을 판정한다. 개선률의 비교 기준인 관측 점수도 같은 정규화로 계산한다. 이 시뮬레이터
  호출은 실험 행동이 아니며, 결과는 어떤 상태에도 쓰지 않는다.

## 5. 판정 모델

- Claude Code 헤드리스 `claude-opus-5-5`, effort `medium`. 하네스의 Claude CLI 격리(빈 임시 디렉터리, 내장 도구와
  사용자 설정 없음)를 그대로 쓰고, 출력은 JSON 스키마로 받는다.
- 답 하나에 호출 3~4회다: 주장 추출, 충실도 판정, 문맥 정밀도(제품만), 역질문 생성. 항목마다 한 번만 판정한다.
- 블라인드: 두 조건의 문맥을 같은 형식의 문단 목록으로 편다. 공통 부분은 과제 공개 정보, 관측, 앞선 상담이다. 제품은
  카드 하나가 문단 하나이고, 일반 조건은 초기 텍스트를 문서·절 단위로, 기억을 기록 단위로 나눈다. 문단 id와 답 속의
  id는 중립 id(P01…)로 바꿔 주고 코드가 되돌린다. 조건 이름과 모델 이름은 넣지 않는다.
- 판정 모델은 숨은 기준값을 보지 않는다(공개 과제 정보만 받는다).
- 프롬프트 버전(`rag-judge-v1`)과 해시를 평가 manifest에 고정한다. 호출이 유한 재시도 뒤에도 실패하면 그 항목의
  지표를 "판정 불가"로 두고 세며, 기본값으로 채우지 않는다.

## 6. 집계와 보고

- 조건별 평균(답 단위 평균. 주장 수준 지표는 주장 합산 비율도 함께 적는다)과 차이(제품 − 일반).
- 구간: 에피소드를 단위로 조건 안에서 복원 추출하는 군집 부트스트랩 10,000회, 95% 백분위 구간.
- 주지표는 표본 충실도의 조건 간 차이와 그 구간이다. 나머지는 보조 지표이고, 과제별 표는 서술용이다.
- 공개 산출물(`report.md`, `report.json`, `items.jsonl`)에는 추천의 성공 여부·정규화 점수·개선 여부만 싣는다. 숨은
  문턱과 원시 TON·수율은 `private/rag_eval/<out>/`에만 둔다.
- 결과 해설은 실행 후 `docs/implementation/results-<실행일>-rag-eval-v3.md`에 쓴다.

## 7. 실행과 코드

- 위치: 리포 최상위 `rag_eval/` 패키지(labgene을 읽기 전용으로 import)와 평가 프로필 `configs/rag_eval.yaml`. v3의
  frozen 프로필·분석 계획·세트 계획과 `src/labgene`은 수정하지 않는다. 상담 구성은 v3 프로필을 읽어 그대로 쓰고, 평가
  프로필에는 판정 역할과 상한만 더한다.
- 명령: `python -m rag_eval run --run-dir artifacts/main-v3 --out artifacts/rag-eval-v3-01`. 순서는 다음과 같다.
  1. 표본 선택 → `sample.json`(해시 포함)
  2. 전 상담 코드 지표(기계 검사, 추천 정답성)
  3. 표본 문맥 복원과 복원 일치 확인
  4. 표본 판정
  5. 집계와 보고서
- 산출물(`artifacts/<out>/`): `manifest.json`(대상 run id, frozen manifest·v3 프로필·평가 프로필 해시, 프롬프트 버전·
  해시, 판정 모델·effort, 표본 해시), `sample.json`, `items.jsonl`, `costs.jsonl`, `report.json`, `report.md`.
- 비용 상한(평가 프로필): 판정 호출 400회, Gemini 임베딩 $0.5, 복원에 필요한 요약·게이트 호출은 v3 역할 설정 그대로
  50회 이내. 상담 모델(Luna) 호출은 0회. 모든 호출은 이 평가의 비용 기록에만 남는다.
- 중간에 멈추면 같은 `--out`으로 다시 실행해 끝난 항목은 건너뛴다.

## 8. 보고서에 적을 한계

- 판정은 LLM(Opus 5.5 medium)이 한 번 한다. KG 관계도 Opus가 추출했으므로, 같은 계열의 판정이 KG 카드에 우호적일 수
  있다.
- 두 조건의 질문과 궤적이 달라 짝 비교가 아니다. 세트 반복은 1회이고, 에피소드 수가 적으면 구간이 거칠다.
- 사실·추론 구분과 카드 관련성은 판정 모델이 정한다.
- 일반 조건은 `initial:text` 한 덩어리를 인용하므로 인용 지표의 구조가 다르다. 조건 비교는 충실도로 한다.
- 문맥 정밀도는 제품에만 있다.
- 도구로 연 자료는 복원하지 못한다(복원 불일치로 표시).
- 추천 정답성은 에뮬레이터 안의 결과다(U24). 연구원이 그 추천을 따랐는지와는 별개다.
